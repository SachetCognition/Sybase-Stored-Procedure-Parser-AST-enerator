5.1 AcmeERP.usp_CalculateFifoCost

PropertyValue
DomainInventory / Costing
ComplexityMEDIUM
Tables ReadAcmeERP.StockMovements
Tables WrittenNone (read-only query)
AST NodesCTE, Window Function (SUM OVER), SELECT, WHERE
OutputResult set: FifoCostEstimate DECIMAL

Parameters

NameTypeDescription
@ProductIDINTProduct to calculate FIFO cost for
@QuantityRequestedINTQuantity to cost using FIFO method

Algorithm

1
Build CTE CTE_FIFO over IN-direction movements for the given product
2
Calculate running total using SUM(Quantity) OVER (ORDER BY MovementDate)
3
Filter rows where RunningTotal ≤ @QuantityRequested
4
Return AVG(UnitCost) of qualifying batches as the FIFO cost estimate

Control Flow Diagram

11. Performance Observations

Stored ProcedureApproachAvg Execution TimeObservation
usp_CalculateFifoCost Set-based (CTE + window function) ~0.020s Efficient — single pass with running total
usp_ConvertToBase Sequential IF/ELSE with up to 3 queries ~0.025s Acceptable — could be combined into single query with COALESCE
usp_ProcessFullPayrollCycle CURSOR-based (per-employee conversion) ~0.160s Cursor overhead — could be refactored to set-based JOIN with ExchangeRates

Optimization Recommendations

1
Payroll SP: Replace the PayrollCursor with a set-based UPDATE JOIN against ExchangeRates. This would eliminate the per-row cursor overhead for 1000+ employees.
2
Currency SP: Combine the 3 sequential SELECTs into a single query using COALESCE with subqueries for each fallback level.
3
FIFO SP: Already set-based and efficient. Consider adding an index on StockMovements(ProductID, Direction, MovementDate) for large datasets.
